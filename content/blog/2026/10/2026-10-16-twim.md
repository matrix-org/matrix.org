## Dept of Social Good 🙆

[Amandine](https://matrix.to/#/@Amandine:matrix.org) says

> 🇪🇺 Europe is working towards more Digital Sovereignty, and as such taking open source and digital commons at the forefront of regulation and political discourse.
>
> From Tchap in France 🇫🇷 to BundesMessenger and openDesk in Germany 🇩🇪, via BEAM in Belgium 🇧🇪, LuxChat in Luxembourg 🇱🇺, and many more, Matrix underpins government communications across Europe: it makes it an obvious case study of how to scale digital commons. However, despite Matrix’ popularity, only one government agency, France's DINUM, commits to support the open standard they all rely on by being a member.
>
> 💡 That gap is exactly one of those the new [Digital Commons EDIC (DC-EDIC)](https://digital-commons-edic.eu/) could close and with this truly impact Europe’s implementation of digital commons. Drawing on 12 years of building Matrix, we've set out how the DC-EDIC can make the most of its five goals, taking a leaf out of the World Health Organization's book. Our suggestions include:
>
> - Build a trusted index of open source projects and vendors
> - Pool funding across Member States
> - Fund the guardians of open standards, not just new code
> - Give policymakers real evidence on costs, privacy and security
>   … and more!
>
> Europe doesn't lack open source builders. What it needs is a body that does the unglamorous work that keeps everyone's lights on.
>
> Read our recommendations in [this blog post](https://matrix.org/blog/2026/10/14/build-open-source-europe-how-dc-edic-help/).

> ### Spec Updates
>
> There's been a *huge* push in the last week to get Matrix 2.0 ready. A total of 187 comments across [all Matrix 2.0 MSCs](https://github.com/matrix-org/matrix-spec-proposals/issues?q=state%3Aopen%20label%3Amatrix-2.0) in the last week alone! A massive thanks to the authors and all of the reviewers for their work here.
>
> The result is that 8 more Matrix 2.0 MSCs entered FCP this week! Sticky Events has received the most scrutiny, but both it and the implementation are now in a good place in the SCT's eyes.
>
> * 🟢 MSC4140: Cancellable delayed events — Merged.
> * 🟢 Clarifications for MSC4140: Cancellable delayed events — Merged.
> * 🟢 MSC4354: Sticky Events — **Entered FCP on 15 October**, up from 2 / 8 approvals. Earlier implementation/testing, expiry and visibility concerns are cleared. Federation catch-up flicker and stale notifications are an [explicitly accepted remaining risk](https://github.com/matrix-org/matrix-spec-proposals/pull/4354#discussion_r4288749943), not a solved problem or outstanding blocker. Latest visible follow-up is an RTC example correction.
> * 🟢 MSC4551: Sliding Sync Extensions: Receipts — **Entered FCP on 13 October.** Replaces the closed MSC3960.
> * 🟢 MSC4538: Sliding Sync Extensions: To-Device messages — **Entered FCP on 13 October.**
> * 🟢 MSC4543: Sliding Sync Extensions: End-to-end encryption — **Entered FCP on 13 October.** The token-acceptance feasibility question has been answered.
> * 🟢 MSC4548: Sliding Sync Extensions: Account data — **Entered FCP on 13 October.** Discussion about implementation coverage for enabling/re-enabling and [whether Synapse actually differs from the proposal](https://github.com/matrix-org/matrix-spec-proposals/pull/4548#discussion_r4209523167) remains open.
> * 🟢 MSC4143: MatrixRTC – Real-time communication over Matrix — **Entered FCP on 15 October.** Implementation/migration discussion is now resolved. This week’s slot-ID versus event-ID concern was closed by reverting the proposed slot-event-ID addition. Sticky Events is no longer an outstanding dependency concern.
> * 🟢 MSC4195: LiveKit transport for MatrixRTC — **Entered FCP on 15 October.** Abuse-mitigation discussion is resolved. A new mandatory-multi-SFU objection was [addressed by allowing publishing to a remote SFU](https://github.com/matrix-org/matrix-spec-proposals/pull/4195#discussion_r4270402427).
> * 🟢 MSC4196: Voice and video calling application for MatrixRTC— **Entered FCP on 15 October.** The server-presets discussion is resolved in favour of client-managed slot creation.
> * 🟡 MSC4480: Sliding Sync Extension: Sticky Events — **Now proposed for FCP, 1 / 8 approvals.** Blockers remain around room-scope transitions, enable/disable behaviour, long-poll wakeups and lazy-loaded membership for rooms leaving scope. Global `pos` is now incorporated, but [how clients detect backlog exhaustion](https://github.com/matrix-org/matrix-spec-proposals/pull/4480#discussion_r4288444314) remains under discussion. Implementation also needs checking by the SCT.
> * 🔴 MSC4075: MatrixRTC invites and notifications — **Still in proposal review.** Earlier invalid-event and slot-lifecycle questions have been addressed; cross-device ringing is now documented as a limitation, but not fixed. A new potentially blocking [session-identity/simultaneous-invite question](https://github.com/matrix-org/matrix-spec-proposals/pull/4075#discussion_r4291994109) remains open. Sticky-object validation has an author response awaiting closure, and the PR still carries `needs-implementation`.
>
> Given the 5-day FCP timer, we should see the majority of these actually become accepted by the conference 🎉 A couple MSCs are still outstanding (SS extension: sticky events and MRTC invites/notifications) but the core of everything is there, and those MSCs won't be left out of the 2.0 release.
>
> For now, we can celebrate how much work has been put in to bring these exciting additions to the spec 🥂

### Zendrite v3.5.0

[pat-s](https://matrix.to/#/@pat-s:matrix.devxy.io) says

> [Zendrite](https://codefloe.com/pat-s/zendrite), the Dendrite fork written in Go, released v3.5.0.
> This release focuses on Element Call and on catching up with the spec.
>
> **Element Call**
>
> - [MSC4140](https://github.com/matrix-org/matrix-spec-proposals/pull/4140) delayed events, which Element Call uses to remove crashed clients from calls, including delayed sticky events.
> - [MSC4354](https://github.com/matrix-org/matrix-spec-proposals/pull/4354) sticky events in sync v2 and sliding sync, which Element Call's `matrix_2_0` MatrixRTC mode needs.
> - [MSC4222](https://github.com/matrix-org/matrix-spec-proposals/pull/4222) `state_after` in sync v2.
> - Optional call guest accounts, so people without a Matrix account can join a call by link without open registration; they can only take part in calls and expire after a configurable lifetime.
> - An [end-to-end deployment guide](https://zendrite.pat-s.me/administration/matrixrtc/) covering LiveKit, lk-jwt-service, the standalone Element Call app and the Helm chart.
>
> **Spec support**
>
> - `/versions` now advertises Matrix v1.3 through v1.6, which also unblocks bridges such as mautrix-telegram that refused to start against v1.2.
> - Jump to date (MSC3030) now asks other servers when local history may hide a closer event.
> - Custom profile fields (MSC4133), refresh tokens (MSC2918), room type filters for the public room directory (MSC3827), leave reasons (MSC2367), key backup deletion (MSC1219), and the remaining Matrix v1.2 MSCs.
> - Application services now receive redactions.
>
> **Fixes**
>
> - Sliding sync timelines now apply history visibility, so users can no longer read messages from before they were allowed to see them.
> - Server ACL globs match against the whole server name.
> - Redacting v11+ member events keeps `third_party_invite.signed`.
> - The built-in NATS server is now 2.15.1, which fixes a broker replica that stopped catching up after rejoining on its old storage; HA deployments running their own brokers should upgrade them to 2.15.1 too, and the HA guide explains how to spot and recover a stuck replica.
>
> Release notes: <https://codefloe.com/pat-s/zendrite/releases/tag/v3.5.0>

> This week we have a new release, [Synapse 1.163.0](https://github.com/element-hq/synapse/blob/release-v1.163/CHANGES.md#synapse-11630-2026-10-14). To highlight:
>
>  - We can finally see light at the end of the tunnel with our Matrix v1.17 project. Synapse now advertises support for Matrix v1.14 and v1.15 ([#20137](https://github.com/element-hq/synapse/pull/20137), [#20286](https://github.com/element-hq/synapse/pull/20286)), and Matrix v1.16 and v1.17 will come as part of the next release (already merged). Of course, the spec keeps evolving, so the march isn't over, but we've accomplished the concrete goal we set out for this quarter! 🎉
>  - The experimental [MSC4354](https://github.com/matrix-org/matrix-spec-proposals/pull/4354) Sticky Events implementation got a number of updates to improve robustness. Synapse now catches up remote homeservers with any sticky events they may have missed ([#20165](https://github.com/element-hq/synapse/pull/20165)), handles sticky events being redacted ([#20232](https://github.com/element-hq/synapse/pull/20232)), makes sure new joiners know about all sticky events in the room ([#20233](https://github.com/element-hq/synapse/pull/20233)), and uses sharded tokens to prevent race conditions when using workers ([#20186](https://github.com/element-hq/synapse/pull/20186)).
>  - Fixed an edge case where the push badge count could undercount. Because it needs specific conditions and because most clients calculate the badge count themselves, this might not be a very commonly visible problem in the wild, **but** it fixed a Complement test flake that has been plaguing us 🙏 ([#20237](https://github.com/element-hq/synapse/pull/20237)).
>  - On the Rust side, we reduced contention on the Python GIL (global interpreter lock), and the need to block waiting for it, when handing off data from async Rust to Python ([#20252](https://github.com/element-hq/synapse/pull/20252), [#20267](https://github.com/element-hq/synapse/pull/20267)).
>  - While it's "just" a dependency swap, URL previews now parse HTML with `beautifulsoup4` instead of `lxml`, moving us off `libxml2`, which is [no longer maintained](https://gitlab.gnome.org/GNOME/libxml2/-/commit/9c80a89af2fdf4f853892f84e46580f4902658ba). It's a nice bit of maintenance work that even lets us remove some of our own code, since `beautifulsoup4` handles charset detection for us (a rare PR that removes more code than it adds 🔥) ([#19301](https://github.com/element-hq/synapse/pull/19301), thanks to [@clokep](https://github.com/clokep)).
>
> Thank you to all our contributors for helping to make Synapse the best it can be. As always, feel free to stop by [#synapse:matrix.org](https://matrix.to/#/#synapse:matrix.org) to join in on the discussion, and if you encounter a bug, make sure to [report it](https://github.com/element-hq/synapse/issues/new/choose).

### Vommet ([website](https://vommet.app))

[Dark Collective](https://matrix.to/#/@dark:nether.im) announces

> A Discord-like Matrix client that doesn't suck.
>
> [Vommet](https://vommet.app) is an LLM-assisted fork of the excellent [Commet](https://commet.chat) Matrix client. I run a large Discord community I've been trying to move to Matrix for years, but no matter what client we tried, people kept bouncing off it. Everyone had a missing feature (Telegram sticker packs, screen sharing with audio on Linux, UI friction, etc.) that sent them back to Discord, even as recent policy changes have left many of our members wishing for a real alternative. So I've been working with community members one by one, finding every missing feature, bug or UI wart that makes Matrix hard to use, and fixing it.
>
> Commet doesn't accept LLM contributions, which we respect, so nothing goes upstream. The name is a joke about AI slop and our [rapid release cadence](https://nether.codes/nether/vommet/releases). But like the title says, it doesn't suck. Actually, we think it's really, really good.
>
> **Voice and calls**
>
> - Discord-like voice rooms with a "Voice Connected" card, mute and deafen next to your name, and volume sliders
> - Push to talk, with a key that works while you're in a game (Windows and X11) and a hold-to-talk button on phones
> - Watch streams like Discord, plus screen sharing with audio: on Linux, pick any app's audio or everything except voice chat apps
> - Noise suppression in calls (RNNoise or DeepFilterNet3)
> - Calls in any room or DM, not just voice rooms
> - Voice chat with your Discord friends using [Nether Voice Bridge](https://nether.codes/nether/nether-voicebridge)
>
> **Chat**
>
> - Mass-import your favorite sticker packs from Telegram (and Signal), right in the app, into shareable sticker rooms
> - Several pictures posted together show up as one Telegram-style mosaic, and you can flip through a room's pictures like a gallery
> - Send messages while offline, like Telegram: they go out when you're back, even after a restart
> - Better thread support, with several display modes for thread cards
> - Voice messages, and (just landed, desktop only so far) on-device transcription like in Telegram
> - Spoilers on pictures, bridged GIFs that actually play as GIFs, and plain `example.com` text turned into links like on Telegram
> - Forwarding, drafts, multi-select, a formatting bar, and Discord-style `<t:timestamp>` times shown in everyone's own time zone
>
> **People and spaces**
>
> - Explore: browse any homeserver's public room directory, and peek inside a space before you join it
> - See which spaces and rooms you share with someone on their profile
> - Block people, with a clear "You blocked" notice in the DM
> - Get banned from a room and it stays in your list, greyed, with the mod's reason, so you can keep reading until you choose to leave
> - Banners for spaces and rooms, and better nested subspaces
> - When joining a space, pick which of its rooms and subspaces you join
>
> **Look and feel**
>
> - Lots of UI improvements (see the screenshots on the website). When in doubt I rip off Discord, the good parts at least.
> - Tons of extra themes and a Telegram-style theme editor, plus a font picker with dyslexia-friendly options
>
> **Encryption and onboarding**
>
> - A first-time setup that explains cross-signing and recovery keys in plain language, plus many new and fixed settings around cross-signing
> - Share history when inviting someone to an encrypted room, and receive it when you're invited (MSC4268)
> - Preview an invite before accepting, and decline and block in one go
>
> **Under the hood**
>
> - Lots of fixes for upstream bugs in Commet and the Famedly Matrix Dart SDK fork it uses
> - Aggressive performance work and sliding sync. Cold start on my phone is three seconds vs thirty-plus on Commet.
> - Notification and UnifiedPush fixes on Android
>
> **Widgets**
>
> - Widget support with an in-app picker, our own widgets like Park Chess, and Watch Together, which we're testing in our rooms, keeping a video in sync for everyone
>
> And lots more!
>
> The project is moving fast and we have a ton of features planned. It's still very early, so there are bugs to squash every day. We'd love for experienced Dart and Flutter developers to check out the codebase. Even if you're not a programmer, using the app, turning on the opt-in telemetry and reporting bugs in our [developer channel](https://matrix.to/#/#vommet:nether.im) helps immensely.
>
> There are testing builds for Linux (Flatpak), Android and Windows. Nothing for Mac or iPhone yet; if you have Apple hardware, I'd love help testing iPhone builds.
>

### Humatrix

[Hannes](https://matrix.to/#/@hannes:gumarcks.de) says

> One-Command Installer for Matrix in Debian with a more human control
>
> **What I wanted to solve**
>
> As I want to use Matrix with others, it's essential that the setup is as easy as possible for starters, all other everyday tasks should be possible without the terminal.
>
> ![WebGui for Usermanagement, Adminpanel secured by 2FA](/blog/img/DQTdsPzvxKLXgMDLeaAPyZKS_image.avif)
>
> Since I, as an admin want full control but don't want to be asked for everything, it's possible to give users the right to invite other users – to the server or directly to a group of it.
> So I can adjust if one user is allowed to invite others generally, allowed to invite X others or isnt allowed – by that I can see branches, who invited whom and so on; I can also "ban" a user which aborts all their pending invites to others.
>
> ![Screenshot of the invitation GUI in Humatrix](/blog/img/WBPRfkGJhsdNCFqGiflinRNY_image.avif)
>
> My Installation mostly brings as new feature the "Human-Interface" (WebGui), so I thought Humatrix is a fitting name :D
>
> **Features**
>
> - One-Command installation including everything you need for a Matrix server (Synapse, Element Web, coturn (calls), nginx, Let's Encrypt, PostgreSQL, and a Backup-Plan)
> - The installer checks the DNS and gets the SSL certificate;
>   if a proxy is running, it leaves TLS to the proxy
> - in the WebGui you'll get informed if updates are available and to start the updates.
> - Everything is available in German and English
> - After the installation, a User-Guide is created including How-To Screenshots and the generated first time password
> - The settings (Language, Proxy yes/no, Adminname, Domain and mail) are part of the Install-command and described in the Github Readme.
>
> **About the Code**
>
> My Job isn't writing Code, but setting up systems and checking Code – so I can read it and know what is essential for avoiding security-issues - but I can't write (that fast).
> So yes, for the writing I used AI – but I read over all and check all functions. If that's already a no go, please inform me.
