## Dept of Clients 📱

### Tesseract ([website](https://surakin.github.io/tesseract/))

[Marco](https://matrix.to/#/@surak:gnomos.org) announces

> Hello, folks! It's been some time since the last update, so here it is:
>
> Tesseract is now in beta! The last missing features (invite dialog and room moderation: kick/ban/unban) were added in 0.9.0.
> This doesn't mean new features aren't coming; only that it should be possible to use it as your main daily desktop client.
>
> There have been 7 releases since the last TWIM post and there are too many changes to list here, but I'd like to mention call rooms, directory browser, user status, and simpler encryption setup and recovery.
>
> About encryption setup: in the ongoing effort to make this easier and more user-friendly, a new silent recovery setup was added (only for accounts without recovery set up). Tesseract will set the encryption and recovery silently and save the recovery key in the OS secure storage (only if available), and then periodically nag the user to make sure it is saved in a better/safer place. This way a new user will have a fully functional client with all the end-to-end encryption capabilities set up, right after login. (This can be disabled with a build flag, in case a build without this functionality is needed). Hopefully this will make onboarding new users much simpler.
>
> On a different note, Tesseract is now [available](https://apps.microsoft.com/detail/9nz8v8tcnvjw) in the Microsoft Store, which is something I never imagined I would say out loud, but here we are 🤷🏻 (easier installs, with proper signed binaries, for free; how could I resist?)
>
> For the curious, [here](https://github.com/surakin/tesseract/releases) are all the recent changelogs. Feel free to drop by the official [room](https://matrix.to/#/#tesseract-client:matrix.org)!

### Element X Android ([website](https://github.com/vector-im/element-x-android))

Android Matrix messenger application using the Matrix Rust SDK and Jetpack Compose.

[Jorge](https://matrix.to/#/@jorgem:element.io) says

> Hello everyone, this week on the Element X Android team we've been focused on:
>
> - Improving the multi-account feature (still behind a feature flag). There is a better UX for selecting which account you're using and more places where this is useful, like when sharing something coming from outside the app.
> - Global search: we're now able to automatically back paginate and add past history to the search index so you can search for older messages in your encrypted rooms. The feature should be available shortly, too!
> - Multi-selection of messages in rooms: you'll be able to select and forward several messages into other rooms, instead of having to do it one by one. There are some limits set to prevent spamming. The feature is still a work in progress, so it's behind a feature flag.
> - Element call native: the VOIP team has been working really hard to deliver a better experience than webview integration, which is known to have limitations and audio bugs we can't fix because the webview environment limits us, so they built a native experience instead. This is behind a feature flag for now, but if you can test it, we'd love to know your feedback.
> - Unread counts in the room list: we're displaying unread notification counts in rooms now and we've improved their UI too. With backpagination, they should be way more accurate now, although we know there are still some corner cases we need to fix. There is also the option now in the app to display only unread notifications in the room list, instead of displaying also an indicator for unread messages in rooms you don't really care about.
> - Improving the send queue: we know there are some issue related to the send queue after we changed its logic to try to enforce the order of sent events and are working on fixing those.
> - We're now automatically dismissing notifications for rooms we know are fully read from other devices.
>
> And many other bug fixes and improvements.

## Dept of SDKs and Frameworks 🧰

### djangomatrixappservice

[Fabian](https://matrix.to/#/@fabian:alertrix.net) says

> Do you want to manage a larger amount of bots (lets say you want to write another bridge)? How about managing them through a web interface? Or just send notifications from your webservice to your users? How about implementing all this in a powerful, python-based web framework?
>
> Well, here is a solution to that! I have completely rewritten pretty much all of the code in the central component of a larger project that i started two and a half years ago during my funding from [PrototypeFund](https://www.prototypefund.de/projects/alertrix).
>
> I call this central component `djangomatrixappservice`, because it is a Django app that can interact with the matrix application service api. It comes bundled wih a matrix-nio based client.
>
> It supports multiple auth types:
>
> - Application service identity assertion
> - Rotating OIDC/MAS tokens
> - Legacy password login/long-lived tokens
>
> Activity is triggered by…
>
> - your code
> - push notifications directly from the homeserver to your web service
> - application service transactions to your web service
>
> There is no long-running sync-requests in the background, so this does scale to as many accounts as you like without requiring more energy.
>
> Despite having found ways to unit test a lot of it, there are still important parts that are not covered by that yet, so currently it is very experimental.
> I am posting this now, because I am confident that this approach is abstract enough to fulfill a lot of developer needs, but provides enough guidelines to become a common base for different projects. Since the initial migration for a django project is pretty important to get right, this is the perfect time to gather feedback for that.
>
> Next steps include:
>
> - Add more documentation on how to get started
> - Increase the coverage of unit testing
> - Gather experience from more little projects
>
> The code is hosted on codeberg: <https://codeberg.org/alertrix/djangomatrixappservice>
>
> Feel free to reach out to me in the [#twim-offtopic](https://matrix.to/#/#twim-offtopic:matrix.org) room or [#djangomatrixappservice:alertrix.net](https://matrix.to/#/#djangomatrixappservice:alertrix.net)
>
> I would love to hear your feedback (how would you want to integrate it in a project) and I am looking forward to posting more about this in the future!
