### Arminius - A new enterprise homeserver in development

[Nico](https://matrix.to/#/@deepbluev7:neko.dev) says

> Heya, Nico here, with my corporate hat on!
> 
> For the last almost 2 years my team at Famedly have been secretly working with
> the BWI on a new homeserver for them. Now we finally published the repository
> for it and will continue working in the open from now on.
> 
> However, the homeserver is **not done yet**. So please do not actually use it
> yet. We want to first make sure it behaves as a proper citizen of the federation
> and we still have a few complement tests to pass as well as do a proper audit
> and fixup some of the corners we have cut at the start of development.
> 
> You might be wondering why one would want to write a new homeserver. We gave one
> explanation at The Matrix Conference and thanks to the amazing video and
> conference team as well as all the volunteers, you can actually watch the
> recording here:
> <https://conference.matrix.org/watch/#why-is-there-rust-in-our-matrix>
> 
> If you are not much of a video fan, the brief gist of it is:
> 
> - We want a scalable homeserver, that we can run in a high-availability setup
>   without any single process of failure. (That's what SPOF stands for, right?)
> - We want the server to be reliable, because surprises are for people, not
>   computers!
> - And we want it to have all the enterprise-y fun bits like easy to deploy on k8s
>   and integrate with all the enterprise tools the BWI likes or rather gets to
>   deal with.
> 
> Long term this will also be our base for our MLS work.
> 
> So far it has been pretty fun developing a homeserver while trying to follow the
> spec and please do expect a few spec clarification PRs as well as contributions
> from complement from us. You don't often get to see the spec from that lens and
> I hope we can leave the spec in a better place for the next 20 homeservers!
> 
> If anything here sounded interesting, do check out our
> [repo](https://gitlab.com/bundesmessenger/backend/neo/arminius/arminius), but
> don't look too closely, it is always a bit embarrassing to present something you
> have built!
> 
> As an aside, we also built our own test suite and have been [trying it
> out](https://gitlab.com/bundesmessenger/backend/neo/arminius/arminius/-/merge_requests/2641)
> on Continuwuity, which has been quite interesting. It is a lot of fun to work
> with others in the ecosystem!
> 
> We also plan to make an MSC out of our
> [homeserver migration format](https://arminius-f3fbca.gitlab.io/adrs/homeserver-migration.html)
> once we gathered some experience with it, which will surely make development of
> other homeservers more interesting to people, who already have a homeserver
> deployed.
> 
> That is all I have for you this time. You likely will have to wait for the next
> update for a while, but we do intend to share when Arminius becomes usable and
> you can try it out. In the meantime you can always find us on Matrix!

### Zendrite ([website](https://zendrite.pat-s.me))

[pat-s](https://matrix.to/#/@pat-s:matrix.devxy.io) announces

> [Zendrite](https://codefloe.com/pat-s/zendrite), the Dendrite fork written in Go, released v3.7.0.
> This release catches up with Matrix spec v1.16 to v1.19, adds two moderation features and repairs rooms whose stored state went wrong.
> 
> **Spec support**
> 
> - `/versions` now advertises Matrix v1.16 through v1.19.
> - [MSC4108](https://github.com/matrix-org/matrix-spec-proposals/pull/4108) QR code login, which lets a new device sign in by scanning a code from a device that is already logged in, using the rendezvous from [MSC4388](https://github.com/matrix-org/matrix-spec-proposals/pull/4388).
> - [MSC4306](https://github.com/matrix-org/matrix-spec-proposals/pull/4306) thread subscriptions, so users can follow individual threads.
> - [MSC4262](https://github.com/matrix-org/matrix-spec-proposals/pull/4262), which delivers profile updates over sliding sync.
> - The Matrix v1.17 changes [MSC4190](https://github.com/matrix-org/matrix-spec-proposals/pull/4190), [MSC4210](https://github.com/matrix-org/matrix-spec-proposals/pull/4210) and [MSC4326](https://github.com/matrix-org/matrix-spec-proposals/pull/4326).
> 
> **Moderation**
> 
> - [MSC4284](https://github.com/matrix-org/matrix-spec-proposals/pull/4284) policy servers, which a room can use to screen events before they are accepted.
> - [MSC4380](https://github.com/matrix-org/matrix-spec-proposals/pull/4380) invite blocking, which lets users block unwanted invites.
> 
> **Room state repair**
> 
> - The roomserver repairs state events that were stored under the wrong state key, and skips rejected outliers while doing so.
> - Events that were rejected are rechecked against the repaired state, redactions together with the events they redact, and events together with the rejoin that follows their cited join.
> - Messages that were rejected along with their sender's membership are accepted.
> - Memberships the local repair cannot settle are taken from other servers, and outlier memberships that follow the current state are added.
> - Forked memberships are passed on even when a room has nothing else to add, and the memberships other servers hold for users the repair leaves alone are logged.
> 
> Release notes: <https://codefloe.com/pat-s/zendrite/releases/tag/v3.7.0>  
> Chat: [#dendrite:matrix.org](https://matrix.to/#/#dendrite:matrix.org)

## Dept of Bridges 🌉

### slack2matrix

[Adam](https://matrix.to/#/@adam:bostoncoop.net) reports

> slack2matrix is a one-shot Slack workspace importer that fills in several gaps from prior solutions, including by providing full migration of media/attachments. It imports your Slack export into Matrix as an end-to-end encrypted space. Each Slack channel becomes an encrypted room inside the space. Every Slack user can be mapped to a Matrix user and optionally cross-signed with that Matrix user’s recovery key. Every message, thread, reaction, and file is imported with its original author and timestamp, and all media is encrypted on the client before upload, so the homeserver never stores a plaintext copy of the history. Hyperlinks between messages in different Slack channels are translated to Matrix room hyperlinks.
>
> Try it out: <https://github.com/matrix-axon/slack2matrix>
