### Zendrite ([website](https://zendrite.pat-s.me))

[pat-s](https://matrix.to/#/@pat-s:matrix.devxy.io) reports

> [Zendrite](https://codefloe.com/pat-s/zendrite), the Dendrite fork written in Go, released v3.9.0.
> This release brings faster remote room joins and a long list of newly supported MSCs.
> 
> **Faster remote joins**
> 
> - [MSC3902](https://github.com/matrix-org/matrix-spec-proposals/pull/3902): Zendrite now implements the joining side of faster remote room joins, where a server joins with partial room state.
> - [MSC3706](https://github.com/matrix-org/matrix-spec-proposals/pull/3706): Zendrite also serves partial-state `send_join` responses to other servers.
> - Joins to rooms with a malformed allow list are refused instead of answering 500.
> - `send_join` and `send_leave` events are no longer echoed back to their sender.
> 
> **Spec support**
> 
> - [MSC4155](https://github.com/matrix-org/matrix-spec-proposals/pull/4155) invite filtering.
> - [MSC3881](https://github.com/matrix-org/matrix-spec-proposals/pull/3881) remote toggling of push notifications, and [MSC3890](https://github.com/matrix-org/matrix-spec-proposals/pull/3890) removal of local notification settings when a device is deleted.
> - [MSC4429](https://github.com/matrix-org/matrix-spec-proposals/pull/4429) profile updates in `/sync`.
> - [MSC2815](https://github.com/matrix-org/matrix-spec-proposals/pull/2815), which gives moderators access to the content of redacted events.
> - [MSC3874](https://github.com/matrix-org/matrix-spec-proposals/pull/3874) relation type and [MSC2326](https://github.com/matrix-org/matrix-spec-proposals/pull/2326) label event filters.
> - [MSC3930](https://github.com/matrix-org/matrix-spec-proposals/pull/3930) poll and [MSC4028](https://github.com/matrix-org/matrix-spec-proposals/pull/4028) encrypted event push rules.
> - [MSC4446](https://github.com/matrix-org/matrix-spec-proposals/pull/4446) moving the fully read marker backwards, [MSC4502](https://github.com/matrix-org/matrix-spec-proposals/pull/4502) targeted room member queries and [MSC4491](https://github.com/matrix-org/matrix-spec-proposals/pull/4491) invite reasons in `createRoom`.
> - The room version `org.matrix.msc3389.10` from [MSC3389](https://github.com/matrix-org/matrix-spec-proposals/pull/3389) is offered, and the unimplemented MSC4242 room version is no longer supported.
> 
> **Sliding sync**
> 
> - Long polls no longer drain the database connection pool.
> - The legacy [MSC3575](https://github.com/matrix-org/matrix-spec-proposals/pull/3575) implementation is removed, which fixes missed list room updates.
> - Superseded requests stop quietly instead of logging foreign key violations.
> 
> **Fixes**
> 
> - Identical state events sent by another user no longer bypass the auth rules.
> - `m.room.member` state events now go through the membership flows.
> - Unreachable remote profiles answer 502 and the failure is cached.
> 
> Release notes: <https://codefloe.com/pat-s/zendrite/releases/tag/v3.9.0>  
> Chat: [#dendrite:matrix.org](https://matrix.to/#/#dendrite:matrix.org)

### Synapse ([website](https://github.com/element-hq/synapse/))

Synapse is a Matrix homeserver implementation developed by Element.

[madlittlemods (Eric Eastwood)](https://matrix.to/#/@madlittlemods:matrix.org) says

> This week we have a new release, [Synapse 1.165.0](https://github.com/element-hq/synapse/blob/release-v1.165/CHANGES.md#synapse-11650-2026-11-10). To highlight:
> 
>  - We now have an initial, experimental implementation for efficient [Server Announcements](https://github.com/element-hq/synapse/issues/20240) in Synapse. Server Announcements are for when an admin wants to message *everyone* on the server all at once (like announcing maintenance windows, policy changes, or incident notices), whereas the existing Service Notices are for admins to message people one by one (not efficient when you want to message everyone). There are still some rough edges that you can track in the [epic](https://github.com/element-hq/synapse/issues/20240), but it mostly just works for a client like Element Web. 
>  - The media download endpoints now skip reading from disk for `HEAD` requests so we can respond a lot quicker and avoid the unnecessary disk I/O ([#20368](https://github.com/element-hq/synapse/pull/20368), thanks to [@JimKnoxx](https://github.com/JimKnoxx)).
>  - When using TLS [`listeners`](https://github.com/element-hq/synapse/blob/release-v1.165/docs/usage/configuration/config_documentation.md#listeners) from Synapse itself, we now let the OpenSSL defaults shine through, which allows connections to negotiate the use of the post-quantum hybrid `X25519MLKEM768` key-exchange group when supported by your OpenSSL version ([#20374](https://github.com/element-hq/synapse/pull/20374), thanks to [@bardiharborow](https://github.com/bardiharborow)).
>  - Synapse now prefers the notary response that stays valid longest rather than whichever arrived last. This helps when we receive responses from multiple notary servers which could previously cause event verification to fail ([#20406](https://github.com/element-hq/synapse/pull/20406), thanks to [@AyeshaWaseemAhmad](https://github.com/AyeshaWaseemAhmad)).
> 
> Thank you to all our contributors for helping to make Synapse the best it can be. As always, feel free to stop by [#synapse:matrix.org](https://matrix.to/#/#synapse:matrix.org) to join in on the discussion, and if you encounter a bug, make sure to [report it](https://github.com/element-hq/synapse/issues/new/choose).

### Robrix ([website](https://github.com/project-robius/robrix))

A high-performance, customizable client for power users. Its signature feature is a workspace layout with **dockable tabs** for chatting in many rooms and threads side by side. Written from scratch in Rust for all platforms.

[Kevin Boos](https://matrix.to/#/@kevinaboos:matrix.org) announces

> Hi everyone, I'm happy to share the first ever TWIM update for [Robrix](https://github.com/project-robius/robrix/), our Matrix client that has been in development for over 3 years (oof, didn't realize it had been so long).
> Robrix runs natively on all major platforms and is written from scratch entirely in Rust, and we do mean *from scratch* ... we also wrote the whole underlying UI toolkit ([Makepad](https://github.com/makepad/makepad)) and the platform abstractions framework ([Robius](https://github.com/project-robius/robius)) from scratch in Rust. This gives us unique control over every aspect of the app, including how it integrates with the underlying OS and how its UI behaves and adapts.
>
> ![Robix DesktopUser Interface](/blog/img/robrix-desktop-light.avif)
>
> Robrix's goal is to be highly performant and efficient for power users, even under heavy use. Our signature "cool feature" is a multi-room **dockable tabs** layout (kinda like an IDE workspace), which lets you see and interact with as many rooms and threads as you want, all side-by-side. Each space gets its own dedicated layout too, so you can easily switch between custom room layouts on a per-space basis, instantaneously. We also have a neat multi-pane UI that lets you decide how extra room content is displayed, like pinned messages, threads, members list, room info, etc, even on mobile.
>
> ![Robrix on mobile](/blog/img/robrix-android-phone.avif)
>
> Robrix is also very intentional about letting you access any feature and any UI view on any device. So you can get the nice stacked mobile-like view on desktop, as well as the dockable workspace view on your phone or tablet. No limits! For example, you can zoom the UI to 112.8% if you want to, even on your iPhone.
>
> ![Robrix on a foldable](/blog/img/robrix-android-foldable.avif)
>
> I just got back from The Matrix Conference 2026 where I gave [a talk about Robrix](https://conference.matrix.org/watch/#robrix-a-pure-rust-multi-platform-matrix-client-and-a-peek-at-its-future) and some of our cool future directions, like custom generatable mini-apps that run right alongside your rooms or spaces, with a strict capability-like permissions model to ensure safety.
> 
> Since the conference, we've published two more beta releases, the [latest one is available here](https://github.com/project-robius/robrix/releases/tag/v1.0.0-beta.6). Some nice features we've added recently include:
>
> * 🛡️ Moderator tools to report, mute, kick, or ban users, plus a powerful tool to find, select, and delete spam messages
> * 🎨 Support for custom emoji and MXC URI media
> * 😀 Quick reactions, double-tap to react, and a super fast emoji picker and search popup
> * 🔍︎ Filter bubbles for the rooms list, like other clients but more flexible:
>    * You can *inverse*/*negate* a filter (e.g., "non-low priority rooms") by long-pressing or middle/right-clidking it
>    * We have more filters like "mod/admin rooms", and they can be combined in more ways
> * 🚪 When leaving a space, we show a nice hierarchical view for choosing which rooms/subspaces to leave
> * 📲 Tons of nice mobile-centric features: ↕️ auto-hide top & bottom bars when scrolling, and smoother/better virtual keyboard behavior
> * 🤏 Lots of effort to make the UI perfect and space-efficient on narrower screens & windows
> * 💬 Instantly discover and jump to old rooms (that have been tombstoned & replaced) with one tap
> * Android: ⚡ consistent 120Hz smooth refresh rate while animating, which 🔋 auto-reduces when idle to preserve battery
>    * Plus support for 32-bit devices, Android 8+
> * ⚙️ Tons of new settings to customize lots of Robrix's UI appearance and behavior
> 
> Kindly give Robrix a try, and let us know what you think by joining our Matrix room here: [#robius-robrix:matrix.org](https://matrix.to/#/%23robius-robrix:matrix.org). I'm adding new features (and taking requests!) all the time.

### Nexus ([website](https://nexus.federated.nexus))

Matrix client made with Flutter and a Gomuks backend.

[QuadRadical](https://matrix.to/#/@quadradical:federated.nexus) reports

> Hello TWIM! This week, Nexus v1.1.0 is out, with many new features, quickly followed by v1.1.1!
> 
> You can grab it from the [release page](https://git.federated.nexus/Nexus/nexus/releases/tag/v1.1.1). If you use the Flatpak repo, the nightly builds, or the NixOS module, just update.
> 
> Here's what changed in 1.1.0:
> 
> * Threads: You can now read and reply in message threads.
> * Polls: Create polls, vote in them, and end them.
> * Bot commands: Bots that advertise their commands using [MSC4391](https://github.com/matrix-org/matrix-spec-proposals/pull/4391) now get suggestions in the composer, along with a form for each command's options. Most of gomuks' built-in commands are supported too.
> * Room directory: Browse and join public rooms, and publish your own rooms to the directory.
> * Room upgrades: You can now upgrade a room to a newer room version, and rooms with a tombstone show a banner linking to the new room.
> * Account switcher: You can now be signed in to more than one account and switch between them.
> * Space improvements: You can now view a space's own timeline, and add or remove rooms from a space.
> * Custom emoji and stickers: Send emoji and stickers from image packs, and manage your packs in settings.
> * Reaction details: Hover over a reaction to see its shortcode, or open the new reactions popover to see who reacted with what.
> * Locations: Shared locations are now shown in the timeline.
> * Notification settings: Manage your push rules from inside Nexus, and set per-room notification levels from the room menu.
> * `matrix:` links: Nexus now opens `matrix:` URIs.
> * Event diffs: Changes to power levels, join rules, server ACLs, pinned messages and other room state now show exactly what changed.
> * Power level colours: Display names are now coloured by power level, with a setting to choose between per power level and per user colours.
> * Power level groups: Related permissions are now grouped in room settings, so you can set them all at once, or expand a group to set each one individually.
> * Weighted search: Emoji, user, room and settings search now put the best matches first.
> * Performance and fixes: Lower memory use, and fixes for read receipts.
> * And, as always, a whole lot of bug fixes 🙂
> 
> And in 1.1.1:
> 
> * New media players: Nexus has switched from media_kit to new video and audio players. Videos also no longer autoplay on desktop.
> * Attachment previews: Attachments now show a preview in the composer before you send them.
> * Banned members warning: Before you view a room's banned members for the first time, Nexus warns you that they may have offensive names or avatars.
> * No more Play Services: The Android build was accidentally bundling Google Play Services through the location sharing library introduced in 1.1.0, thought it wasn't used at runtime. That's now fixed.
> * Fixes for crashes when loading audio messages on the Flatpak, and failed audio messages are now handled gracefully.
> 
> #### What's next?
> 
> I'll keep fixing bugs as you find them, and keep working through the features that are still missing. If you run into anything, please let me know in #nexus:federated.nexus.
>

### LiveKit JWT service ([website](https://github.com/element-hq/lk-jwt-service))

Bridging Matrix and LiveKit for Matrix RTC realtime sessions.

[Johannes Marbach](https://matrix.to/#/@johannesm:element.io) announces

> [lk-jwt-service 0.10.0](https://github.com/element-hq/lk-jwt-service/releases/tag/v0.10.0) has been released and brings a bunch of important changes.
> 
> Most prominently, [MSC4195](https://github.com/matrix-org/matrix-spec-proposals/pull/4195) finally landed. 🎉 As a result, this release adds support for the stable Client-Server endpoints as per the merged version of the MSC. The unstable Client-Server endpoints and the legacy standalone endpoints remain supported in addition.
> 
> ⚠️ **IMPORTANT DEPRECATION NOTICES:** Serving the Client-Server endpoints as per the MSC requires setting up lk-jwt-service as an application service on the homeserver. Since the MSC has been accepted, **not running as an application service is deprecated** as of this release and support for it will be removed in future versions. Details on how to configure the application service can be found in [README.md](https://github.com/element-hq/lk-jwt-service#-homeserver-wiring-application-service). For the same reason, fronting more than one homeserver via **`LIVEKIT_FULL_ACCESS_HOMESERVERS` is deprecated** as well and will be removed in future versions. This setting already only affects the legacy endpoints. For security reasons it is strongly [recommended](https://github.com/element-hq/lk-jwt-service#-room-membership-on-the-standalone-endpoints) to only put the one homeserver that lk-jwt-service was set up as an application service for into `LIVEKIT_FULL_ACCESS_HOMESERVERS`.
> 
> A last-minute change in the MSC was to RECOMMEND granting publishing permissions to remote users. This acts as a fallback and allows users to join sessions even if their own homeserver doesn't provide an SFU. Server operators can granularly control whether to allow remote publishing with the new `LIVEKIT_REMOTE_CAN_PUBLISH_HOMESERVERS` environment variable.
> 
> A related change in the final MSC was to RECOMMEND _disabling_ the permission to update one's own metadata for participants. The service now disables this permission by default on tokens. Admins that rely on this feature, may reenable the permission with the new `LIVEKIT_CAN_UPDATE_OWN_METADATA` environment variable.
> 
> [MSC4196](https://github.com/matrix-org/matrix-spec-proposals/pull/4196) also landed and to support the transition to its stable identifiers, the service now maps `m.call#ROOM` slot IDs to `m.call#room`. This means clients will end up in the same LiveKit room regardless of which spelling they used.
> 
> Finally, lk-jwt-service is now able to bind to a Unix socket via the `LIVEKIT_JWT_BIND` environment variable. Thanks to GitHub user @cyberb for contributing this feature.

### Connectivity Tester

[MTRNord (they/them)](https://matrix.to/#/@mtrnord:mtrnord.blog) announces

> A homeserver report now covers more than basic federation reachability, so there are more choices about what to run and more detail to make sense of afterwards. Here are a few highlights from the latest release.
> 
> #### Pick the Checks You Need
> 
> The homepage has a "What to check" picker. Outgoing federation, Client API / Matrix 2.0, MatrixRTC / Element Call, and Neoboard can be selected separately. The result then shows tabs for the categories you chose, instead of making you scroll through checks you did not run. Alerts and probe jobs also have federation-only, standard, and extended presets.
> 
> Some checks are useful when you need a closer look:
> 
> - The room-version check reports which Matrix room versions a homeserver accepts. It sends a signed synthetic federation invite for each version, so the picker labels it as making extra requests.
> - The experimental MSC4496 calendar check looks for the client and federation availability endpoints. It only checks whether those routes exist; it does not request calendar data.
> - The MatrixRTC results show whether the server advertises sticky events (MSC4354), which Neoboard's LiveKit mode and Element Call's Matrix 2.0 mode need.
> 
> #### Read Connectivity Results More Easily
> 
> The results page opens with a health summary. When you scroll down, a slim bar keeps the server name and the main results in view. Section headers show useful status without opening them, and the connectivity section starts with the number of working addresses, TLS versions, and whether ECH is enabled.
> 
> Certificates are grouped instead of repeated for every IP, while each address has its own collapsible details. When a server advertises Encrypted Client Hello, the tester also verifies the public-name certificate a client sees if its ECH attempt is rejected. The report for `mtrnord.blog` shows that certificate alongside the regular one.
> 
> ![Screenshot of the ECH check](/blog/img/H7MIRZiMmP3x2zYaxap3MWVW2JmAVIil_checks-and-ech.avif)
> 
> #### Alerts for Unsteady Connections and ECH
> 
> Alerts now confirm an outage from a window of recent checks: three failures in the last five checks by default. A single successful check during an unreliable spell therefore does not reset the whole confirmation. If a server keeps flipping between down and recovered, its status and history still update, but down/recovered emails and webhooks are suppressed while it is flapping. The recent checks and transitions are saved with the alert, so a restart does not reset that decision. The alerts overview also shows down and recovered changes live.
> 
> Outgoing federation checks also need strong evidence before they treat an address family as unsupported. Even when that result is cached, a background probe keeps checking for recovery. Alerts that have stayed down for more than a week are checked hourly, so recovery is still noticed without running a full check every minute.
> 
> ECH is covered by alert notifications too. For alerts with TLS expiry warnings enabled, the sooner expiring of the regular and ECH public-name certificates sets the warning date. If the ECH certificate expires first, the email and webhook name its public name. A replaced ECH certificate can also trigger the TLS certificate-change notification when that option is enabled.
> 
> #### Share a Report
> 
> The actions are together in one place: get a permalink, re-run the check, or open the Export menu. Markdown now follows the report's sections, including the overview, problems, and individual checks. The redesigned PDF has a light theme for printing and a dark theme for screens, with a verdict banner and compact stat cards.
> 
> ![Image of the PDF](/blog/img/8MpwxNLBKl6pIn4mvvalWiUCtavMadZ4_dark-pdf.avif)
> 
> Try it at <https://connectivity-tester.mtrnord.blog/>. The [changelog](https://phorge.mtrnord.blog/source/mcte/browse/main/CHANGELOG.md), [source code](https://phorge.mtrnord.blog/source/mcte/repository/main/), and [support forum](https://forum.mtrnord.blog/c/matrix-connectivity-tester/support/6) have more details and a place for feedback.
